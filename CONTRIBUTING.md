# Research feedback and maintenance

Maintainer: [@blackscaletech](https://github.com/blackscaletech). Initial implementation and release history are maintained under this account.

Research feedback should identify a reproducible example, the violated accounting or statistical assumption, and its implications for the reported result. Suitable topics include human calibration, missingness, dependence, trace completeness, cost boundaries and registry comparability.

Run the conformance suite before proposing a change. Preserve frozen empirical records and document newly generated evidence separately. Numerical changes require regression tests and a clear account of affected conclusions. Code changes follow the versioning policy.

External submissions require an agreed authorship and licensing policy before integration. Contributors retain appropriate attribution for accepted work. Feedback can be discussed through issues without accepting external commits into the initial release history.

Keep credentials, private outputs, local paths and personal information out of issue reports. Follow [SECURITY.md](SECURITY.md) for sensitive findings.
